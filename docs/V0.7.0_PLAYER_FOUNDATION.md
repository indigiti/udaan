# Udaan v0.7.0 — Player Foundation

## Objective

Create one stable Player identity and event foundation that every future Udaan Arena can reuse.

## Included

- pseudonymous Player identity derived from the existing secure device identity;
- random public Player UUID separated from the internal storage identity;
- encrypted Player persistence with Redis or encrypted-file fallback;
- private-by-default profile;
- goals, language, stage, daily time and Arena preferences;
- encrypted Player Event Ledger;
- /player onboarding and editing;
- /today foundation shell;
- protected /admin/players operational view;
- readiness, health, package and CI integration.

## Explicitly not included

The following remain future releases and must not be represented as completed functionality:

- universal Mission assignment/completion;
- Performance Graph scoring;
- Daily Readiness;
- Udaan Fit programs;
- Momentum/Habit Engine;
- Coach recommendations;
- Teams/Leagues;
- JEE/NEET Exam Arena.

## Privacy contract

- Player profiles are private by default.
- Parent/institution sharing is hard-disabled in v0.7.0.
- Share-card generation is opt-in and still requires an explicit future/share action.
- Future readiness, health, journal and reflection data must not be exposed by /admin/players.

## Storage contract

Player profile files live under protected runtime storage and are encrypted with the existing AES-256-GCM server-storage layer. Redis-backed deployments use persistent Player keys under the Udaan namespace. Event-ledger records are encrypted JSONL under protected runtime storage.

Neither Player files nor event-ledger files may enter Git or a certified release artifact.

## Upgrade / rollback

v0.7.0 does not alter the signed content trust epoch. Existing v0.6.5 Daily 9, rooms, offline learning, QOI and signed content remain compatible.

Rolling back application code does not automatically delete Player/event runtime state. If cryptographic runtime keys are rotated, the controlled security-rotation path purges Player/event state because old encrypted identities cannot be safely reused.
