# Udaan v0.8.0 — Universal Mission Engine

## Objective

Turn the v0.7 Player identity into a real daily training loop without creating separate task systems for academics, fitness, focus and reflection.

## Mission model

Every Mission contains a public Mission UUID, Player UUID, deterministic source key, Arena, Mission type, title, objective, duration, difficulty, optional content references, completion rule, status, scheduled date, timestamps and result metadata.

Supported foundation types are learning, revision, Daily 9, fitness, focus and reflection. Not every type is auto-generated yet; the model is intentionally broader than the first daily templates.

## Daily assignment

`udaan_mission_ensure_daily()` derives a finite daily set from the Player's selected Arenas.

- Learn → Daily 9
- Fit → gentle 10-minute movement break
- Mind → 10-minute distraction-free focus block
- Reflect → private 2-minute reflection

Assignment is idempotent by `source_key`, so reopening Today does not create duplicate missions.

## Completion trust

Daily 9 uses a verified-event rule. The user cannot press a generic complete button for it; it completes from the actual Daily 9 completion path after the journey is fully answered.

Foundation movement, focus and reflection missions use explicit self-report. Udaan records that the user marked the activity complete; it does not claim sensor, medical or content verification.

## Skip behaviour

A Mission can be skipped for the day without punishment. Skip is recorded as an event but does not destroy a streak or reduce a score because v0.8.0 does not implement Momentum or Performance scoring.

A skipped Daily 9 can still become completed later if the verified Daily 9 activity is actually finished.

## Privacy

- Mission state is private runtime data.
- Mission state is encrypted at rest using the current server-storage layer.
- Reflection text is not requested or stored.
- `/admin/players` does not expose Mission detail.
- Mission runtime files are forbidden from Git and certified deployment packages.

## Event Ledger

Structured events emitted: `mission.assigned`, `mission.completed`, and `mission.skipped`.

## Storage

File mode uses encrypted `data/missions/<identity>.json`. Redis mode uses persistent `udaan:missions:<identity>`. State is bounded to the most recent 500 missions per Player.

## Explicitly not included

v0.8.0 does not implement XP/reward economy, overall Player score, adaptive difficulty, Daily Readiness, full Udaan Fit programs, habits/streaks, Coach recommendations, team missions, leagues, JEE/NEET syllabus mission generation, or offline Mission editing/sync.

## Upgrade safety

Existing v0.7 Player data and v0.6 learning/offline data remain compatible. Cryptographic runtime rotation purges Mission state alongside Player/event state because previously encrypted state cannot safely cross the new trust boundary.
